# Agent token economy — Entware Go

## Token economy for ZCode / Codex / Kimi — KAS policy adapted to Entware

Источник: [KAS agent-token-efficiency (issue #420)](https://github.com/saymer-alt/keenetic-auto-setup/blob/main/docs/agent-token-efficiency.md). Это **процессные правила**, не установка TokenEconomizer и не право пропускать release/security gates. Разумный фокус — полезный, проверенный IPK на токен, а не затрата доступной квоты.

1. **Один активный цикл:** записать `Issue/PR | gh-action-build base/head SHA | целевой пакет | конкретный симптом | желаемая проверка | STOP`. Предпочесть завершение незакрытого Draft PR новой работе; в одной сессии планировать не более 3 направлений, но исполнять одну задачу. Избегать пересоздания уже работающего рецепта/проверки.
2. **Точное чтение и риск:** для обычной правки прочесть относящийся к делу `<package>/Makefile`, нужный workflow/скрипт, тест и caller. Для installer/upgrade/`opkg`, удаления/rollback, архитектуры и ABI, SHA-256/provenance, GitHub `latest` cleanup, Actions `contents:write`, upstream sync или dependency/toolchain gate перед правкой **прочесть каждый изменяемый safety-critical файл полностью один раз на точном SHA** и сопряжённые контракты. Не загружать весь Entware SDK и историю всех releases «на всякий случай».
3. **Дешёвый gate первым:** `sh -n`, ShellCheck и конкретные офлайн mocks/pytest до тяжёлой SDK/IPK сборки или QEMU; сверить `go.mod`/Go SDK **до** запуска build. Проверить `opkg` package control `Package/Version/Architecture`, лицензии/NOTICE, подходящий Rust/Go ABI и точное имя asset. Не использовать `PKG_MIRROR_HASH:=skip` и не ослаблять digest/allowlist.
4. **Loop Guard:** после 2 одинаковых FAIL при том же SHA, инструменте и состоянии → новая гипотеза/диагностика или `BLOCKED`, не третий пустой rerun. Нормальный transient CI outage можно повторить при зафиксированной причине. Устаревший `latest`/пропавший asset — сначала сравнить реальный release manifest, а не менять production pins вслепую.
5. **Стоимость сборок:** перед push проверить paths-фильтры, shared-release writer и риск запуска тяжёлых матриц; не запускать release publisher ради docs. Обновление одного пакета не должно затрагивать `mihomo_*`, `beszel-agent_*`, `warpscout_*`, `telemt_*` или `telemt-panel-lite_*` других владельцев. Никаких ночных автоматических прогонов без новой гипотезы и owner GO.
6. **Evidence reuse:** PASS применим только при совпадении SHA/SDK/toolchain/architecture/asset digest/тестового scope. Отделяйте `MOCK PASS`, `CI PASS`, `QEMU PASS`, `FIELD PASS`, `MERGED`, `PUBLISHED`; release `latest` может измениться отдельно. MIPSLE и aarch64 не взаимозаменяемы. Не считайте установку без контроля `opkg status` успешным обновлением.
7. **Лимиты ориентировочные:** небольшой bug 1–3M, ревью 1–5M, средняя правка 5–10M, QEMU/Entware расследование 20–50M токенов. Нет telemetry — `NOT_AVAILABLE`; не оценивать выдуманными числами. При выходе за ориентир сообщить причину, checkpoint и новый план, но не бросать опасную транзакцию. Формат handoff: `Issue/PR | HEAD SHA | проверенные gates | CI URL | проблемы | следующий точный шаг`.

Для TeleMT используйте [`telemt/Makefile`](../telemt/Makefile), [`telemt-panel-lite/Makefile`](../telemt-panel-lite/Makefile), [`docs/telemt-updates.ru.md`](telemt-updates.ru.md), `.github/workflows/build-telemt*.yml`, [Draft PR #33](https://github.com/saymer-alt/entware-go/pull/33) и [эмуляторный Draft PR #68](https://github.com/saymer-alt/router-emulator/pull/68). Файлы будущих installer/upgrade из Draft PR **не считать опубликованными на `gh-action-build`**, пока PR не принят. `--apply`/автообновление на роутере — отдельное owner GO после реального rollback E2E.
