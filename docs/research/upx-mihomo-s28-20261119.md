# UPX для Entware: выборочно, без автоматического сжатия всех ELF
Дата: 2026-11-19. Статус: исследование, не политика публикации `latest`.

## Проверенное текущее состояние источников (ветка `gh-action-build`)

| Пакет | Источник / упаковка | Решение |
|---|---|---|
| `mihomo` | Форк **уже** вызывает `upx -9 --lzma` в `Build/Install`; релиз MIPSel `1.19.34-2` проверен по SHA256 | **Не сжимать повторно**. Исправить init `S99mihomo` → `S28mihomo`, как в официальном `Entware/entware-go` |
| `beszel-agent` | Makefile **уже** использует `upx -9 --lzma` | Не сжимать повторно |
| `warpscout` | Распаковывается официальный уже UPX-сжатый ARM64 release-asset | Сохранить upstream SHA256; не перепаковывать ELF |
| `telemt` (ARM64) | Упаковывается byte-identical upstream MUSL релиз | Не изменять ELF без отдельной проверки, иначе нарушится provenance / digest |
| `telemt-panel-lite` | Byte-identical официальный бинарник; в Makefile `RSTRIP:=:` из-за identity | Нельзя включать глобальный UPX/strip без отдельного согласованного релизного процесса |
| `telemt` (MIPSel experimental IPC) | `strip`: 23,028,440 bytes → UPX 5.3.0: **7,072,700 bytes**, `upx -t` + roundtrip `cmp` PASS | Отдельный IPK; **аппаратная приёмка UPX на KN-1913 пока не завершена** |
| `xray`, `sing-box-go`, `netbird`, `goflow`, `adguardhome-go` | В изученных Makefile не найден явный UPX pack step | Кандидаты только после отдельного arch-by-arch QEMU + device runtime теста |

`UPX` сжимает **исполняемый ELF**, а не shell-скрипты, TOML/YAML, сертификаты и уже сжатые архивы. Он не гарантирует уменьшения RSS: распаковка во время запуска может дать пик RAM/CPU, особенно на MT7621 с 256MB RAM. Некоторые PIE/CGO binaries, с защитой, с embedded resources, или signed binaries могут быть несовместимы. Сжатие ухудшает простую проверку байт-идентичности upstream.

## Условия допуска в package recipe

1. Для конкретной версии/архитектуры зафиксировать source hash, имя файла, размер, описание ELF, интерпретатор и зависимости.
2. `upx -t`; `upx -d` + `cmp` с исходным stripped ELF. Сохранить лицензии.
3. Проверить загрузку/исполнение в совместимом user-space или QEMU-user (если поддерживается), **не подменять этим аппаратный тест**; подтвердить фактический запуск daemon, stop, restart и сеть.
4. Измерить peak RAM/RSS/zRAM, реальный размер на UBIFS, CPU/время старта. На 256MB KN-1913 обязательны временной предел, fail-closed и rollback.
5. Отдельная ревизия пакета и только одна активная init-служба; `rc.unslung` boot order и KAS watchdog не должны конкурировать.
6. Для выпусков: поархитектурная матрица PASS, проверенный комплект IPK, публикация только после отдельного owner GO. Публичный `latest` и фид **не использовать** как хранилище экспериментальных пакетов.

## Почему S28 Mihomo не был готов в этом форке

Официальный `Entware/entware-go/mihomo/Makefile` устанавливает `S28mihomo`; форк `saymer-alt/entware-go` ошибочно всё ещё устанавливал `S99mihomo`, хотя **файл `mihomo/files/S28mihomo` уже существовал** и его байты идентичны `S99mihomo`. KAS `stable` (issue #355) распознаёт оба файла **только если ровно один из них исполняемый и известного SHA256**. Поэтому исправление одноимённого скрипта — пакетная задача, не переустановка KAS.

Для эксперимента на KN-1913 собран `mihomo_1.19.34-3_mipsel-3.4.ipk` путём смены только package revision и `S99`→`S28` в проверенном IPK `1.19.34-2`. Уже сжатые UPX байты ELF и конфигурации неизменны. **Этот лабораторный IPK не является выпуском из SDK и не публиковался в feed/release.** После установки требуется контроль, что старый `S99mihomo` удалён пакетным менеджером, иначе KAS будет правомерно считать состояние неоднозначным.

### Текущее ограничение автоматической публикации

`.github/workflows/build-mihomo.yml` запускается при изменении `mihomo/Makefile`, но `check-version` выбирает `build` на основании наличия текущей upstream версии в опубликованном комплекте. Поэтому *одно лишь изменение S99→S28 в рецепте может не вызвать полную пересборку той же upstream версии*. Для выпуска `-3` нужно отдельное подтверждённое действие/гейт с проверкой release suffix, а не неявная публикация из Draft PR.
