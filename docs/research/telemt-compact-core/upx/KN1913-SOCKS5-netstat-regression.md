# KN-1913 TeleMT UPX: ложный отказ SOCKS5 при dual-stack listener

Дата: 19.11.2026. Объект: Viva KN-1913, KeeneticOS 5.1.9, Entware mipsel-3.4.

## Аппаратное свидетельство
После обновления Mihomo 1.19.34-2 -> 1.19.34-3 (S99 -> S28) на роутере:
- /proc/net/tcp6 показывал TCP LISTEN на :::7890 и IPv4-mapped установленное соединение для 127.0.0.1:7890.
- curl с --socks5-hostname 127.0.0.1:7890 получил настоящий ответ GitHub HTTP 403 с X-RateLimit-Remaining: 0. SOCKS5-соединение успешно, 403 — лимит API GitHub, а не отказ подключения.
- /opt/etc/init.d/S99telemt-ipc-upx start через 60 с выдавал SOCKS5 127.0.0.1:7890 not listening; лог TeleMT не создан, порт 13443 не слушал.
- Причина: grep по netstat принимал лишь 127.0.0.1:7890/0.0.0.0:7890, не :::7890.

## Исправление
Принять в проверке LISTEN три формы: IPv4 loopback, IPv4 wildcard, dual-stack IPv6 wildcard (:::7890), с границами полей и проверкой точного порта. Не делать обязательный запрос к GitHub/Telegram при запуске службы: внешний endpoint может быть недоступен или отвечать 403 и не должен блокировать локальную readiness-проверку.

Добавлен test_socks5_listener.py: реальные варианты netstat (включая KN-1913) и отрицательные тесты портов 78900/17890, пустого вывода и IPv6 loopback-only.

Для недвусмысленной новой сборки увеличена только ревизия экспериментального пакета до 3.5.17-1ipc2upx2. ELF TeleMT не пересобирается из Rust: замороженный исходный IPC2 ELF проходит неизменную процедуру UPX; исправляется сервисный init-файл.

## Ограничения
- Этот коммит меняет исходник в research ветке; он не обновляет автоматически установленный upx1 на KN-1913 и не публикует stable/latest.
- Режим 0644 init / автозапуск OFF сохраняется; не активировать до аппаратного запуска, проверки памяти и Telegram-клиента.
- :::7890 в иных системах теоретически может быть IPv6-only; здесь установленные IPv4-mapped соединения и curl подтверждают IPv4-доступность. Для общего случая отдельный активный TCP/SOCKS5-тест остаётся желателен.
- На KN-1913 после установки UPX оставалось 13100 КиБ NAND, а MemAvailable — около 18 МиБ с MagiTrickle. Включение MT и TeleMT вместе требует отдельной проверки памяти.
