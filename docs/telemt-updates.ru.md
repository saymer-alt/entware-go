# Обновление TeleMT и TeleMT Panel Lite на Entware (ARM64)

Эта инструкция описывает **неофициальные** ARM64-пакеты в [saymer-alt/entware-go](https://github.com/saymer-alt/entware-go). Она намеренно не содержит адресов, доменов, SNI, токенов, пользователей, паролей и приватных конфигураций устройств.

## Как появляются версии

- Ветка репозитория: `gh-action-build`.
- `build-telemt.yml` каждые шесть часов проверяет **стабильный** релиз `telemt/telemt`.
- `build-telemt-panel.yml` каждые шесть часов проверяет релизы `amirotin/telemt_panel` **ветки 1.x**, включая RC. Стабильная версия 0.6.x не считается обновлением 1.x.
- Если новой версии для ARM64 нет, тяжёлая SDK-сборка пропускается. В противном случае проверяются upstream-архив, SHA-256, архитектура, содержимое пакета и лицензии.
- Прошедшие проверки IPK публикуются в [GitHub Release `latest`](https://github.com/saymer-alt/entware-go/releases/tag/latest). Каждый workflow управляет **только своими** файлами; пакеты Mihomo, Beszel и WARPSCOUT не затрагиваются.

**Публикация на GitHub не равна автоматической установке на роутер.** GitHub Release сам по себе не обновляет индексы Entware. Обычная команда `opkg upgrade` увидит пакет только при наличии соответствующего индексируемого feed. Для файлов из `latest` требуется отдельная проверка и локальная установка.

## Имена и версия панели RC

| Семейство | Типичный файл GitHub Release | Имя пакета Entware |
| --- | --- | --- |
| TeleMT | `telemt_3.5.17-1_aarch64-3.10.ipk` | `telemt` |
| Panel Lite | `telemt-panel-lite_1.0.0.rc.3-1_aarch64-3.10.ipk` | `telemt-panel-lite` |

GitHub Release преобразует символ `~` в имени опубликованного файла RC в точку. **Внутри** Entware-пакета версия остаётся `1.0.0~rc.3-1`. Не переименовывайте версию в метаданных IPK: `~rc` обеспечивает правильный порядок RC → стабильный релиз.

## Проверка на устройстве

Подключитесь к роутеру по SSH, затем:

~~~sh
uname -m
opkg print-architecture
opkg status telemt
opkg status telemt-panel-lite
ls -l /opt/bin/telemt /opt/bin/telemt-panel
ls -l /opt/etc/init.d/*telemt*
~~~

Предусмотрен только `aarch64-3.10` (ARM64); не устанавливайте эти файлы на MIPS или ARMv7. Если экземпляр программы установлен вручную и `opkg status` его не знает, **остановитесь**: сначала выясните владельца бинарника и схему запуска. Не меняйте файлы поверх чужой установки вслепую.

Затем сравните версии с [Release latest](https://github.com/saymer-alt/entware-go/releases/tag/latest) и примечаниями разработчиков:

- [TeleMT](https://github.com/telemt/telemt/releases)
- [TeleMT Panel](https://github.com/amirotin/telemt_panel/releases)

## Получение и проверка IPK

Скачать IPK можно из общего Release `latest`. **Перед установкой обязательно сверяйте SHA-256 скачанного файла** с полем `digest: sha256:...` его точного asset в GitHub Releases API:

https://api.github.com/repos/saymer-alt/entware-go/releases/tags/latest

Проверить локальный SHA-256 можно командой `sha256sum /opt/tmp/<имя-файла>.ipk`. Проверьте имя пакета, архитектуру и отсутствие неожиданного понижения версии. Хэш из ответа GitHub обеспечивает проверку целостности полученного файла, но не заменяет проверку доверия к самому репозиторию и журналу CI.

По желанию оператор может хранить на устройстве собственный локальный `telemt-update.sh` с командами `status`, `check`, `fetch core`, `fetch panel`. Такой вспомогательный скрипт **не входит в публичный репозиторий** и не должен содержать секретов. Он может только прочитать версии и сохранить проверенный IPK, без установки или перезапуска служб.

## Резервные копии и установка

**Перед каждым обновлением:**

1. Сохраните прежний рабочий IPK (для корректного отката через `opkg`) либо предусмотрите отдельный проверенный способ его восстановления. В Release `latest` старые IPK могут удаляться после публикации новой версии. Копия одного исполняемого файла сама по себе не восстанавливает состояние `opkg`.
2. В приватном каталоге с правами `0700` сохраните конфигурацию TeleMT, её резервные копии и скрипт запуска. Отдельно сохраните конфигурацию панели, её `data_dir` с `panel-state.json`, служебный скрипт и (если применяется) базу истории/ключи. Для согласованного снимка состояния панели остановите её или используйте официальный экспорт.
3. Проверьте свободное место и сохраните SSH-доступ. Не перезагружайте роутер без возможности ручного восстановления.
4. Проверьте изменения формата конфигурации и требования нового релиза. Новая совместимость TeleMT API с установленной панелью **не гарантируется** одним успешным SDK-билдом.

Порядок ручной установки **уже проверенного** IPK на устройстве, которое действительно управляется `opkg`:

~~~sh
# Пример: подставьте фактически скачанный, проверенный файл
opkg install /opt/tmp/telemt-update/telemt_<версия>-1_aarch64-3.10.ipk
# После успешной установки перезапустите ТОЛЬКО соответствующую службу
/opt/etc/init.d/S99telemt restart
# После запуска проверьте готовность с собственным локальным конфигом
/opt/bin/telemt healthcheck --mode=ready /opt/etc/telemt/config.toml
~~~

Для Panel Lite используйте её собственный IPK и её собственный init-скрипт (нередко `/opt/etc/init.d/S99telemt-panel`). Сначала проверьте конфиг новой версии:

~~~sh
/opt/bin/telemt-panel config check --config /opt/etc/telemt-panel/config.toml
~~~

При ошибке установки или проверки **не обновляйте второй пакет**: проверьте логи и выполните подготовленный откат. Реальные имена скриптов запуска определяются на конкретном устройстве. Установка может прервать подключённых клиентов; планируйте её в удобное время.

## Универсальные скрипты для чистой установки и обновления

В каталоге [`telemt/`](../telemt/) доступны **три публичных файла**, не содержащих персональных настроек:

- [`entware-manager.sh`](../telemt/entware-manager.sh) — общий безопасный движок загрузки/проверки IPK (BusyBox `ash`, без `jq test/match/sub`);
- [`install.sh`](../telemt/install.sh) — **чистая установка пакетов** по явному `--apply`;
- [`upgrade.sh`](../telemt/upgrade.sh) — **подготовка** обновления существующего `opkg`-пакета без его установки.

**Граница возможностей:** эти пакеты устанавливают только двоичные файлы и лицензии. Они **не создают** `config.toml`, Telegram-пользователей, DDNS/SNI, правила NAT, автозапуск или веб-доступ к панели. Настройте всё это **локально** по официальной документации и собственным требованиям. Это особенно важно для «чистого роутера»: сначала должен быть установлен и работоспособен совместимый Entware на ARM64.

Скачайте три скрипта в **одну** папку через SSH на устройстве с уже установленным Entware:

~~~sh
mkdir -p /opt/tmp/telemt-setup
cd /opt/tmp/telemt-setup || exit 1
for name in entware-manager.sh install.sh upgrade.sh; do
  curl -q -fsSL --proto '=https' --proto-redir '=https' \
    "https://raw.githubusercontent.com/saymer-alt/entware-go/gh-action-build/telemt/$name" \
    -o "$name" || exit 1
done
chmod 700 entware-manager.sh install.sh upgrade.sh
~~~

Проверьте содержимое скачанных скриптов перед запуском. Не используйте `curl | sh`. Зависимости: `opkg`, `curl`, `jq`, `sha256sum`, `tar`, `gzip` и стандартные BusyBox-утилиты. `jq` с ONIGURUMA не требуется.

### Чистая установка бинарных IPK

~~~sh
sh install.sh core          # dry-run: проверяет TeleMT IPK, ничего не устанавливает
sh install.sh panel         # dry-run: проверяет Panel Lite IPK
sh install.sh core --apply  # только после просмотра релиза и подтверждения владельцем
sh install.sh panel --apply
~~~

`--apply` запускает только `opkg install /absolute/verified/file.ipk`, затем проверяет установленную версию и бинарник. Если компонент **уже установлен через opkg** или есть бинарник неизвестного владельца, чистая установка **отклоняется**. Никакие службы не перезапускаются. Возможна частичная установка, если второй пакет завершится с ошибкой: команды запускаются **по одному**, не транзакцией.

### Подготовка обновления существующей установки

**Сразу после установки или сейчас, пока в `latest` находится та же версия, сохраните проверенный предыдущий IPK** в постоянный защищённый каталог. Без этого будущий откат `opkg` может оказаться невозможен: `latest` удаляет предыдущие IPK после публикации новой версии.

~~~sh
sh entware-manager.sh status
sh entware-manager.sh check core
sh entware-manager.sh check panel
sh entware-manager.sh cache core
sh entware-manager.sh cache panel
~~~

`cache` разрешён лишь если версия `opkg` **точно равна** опубликованной. Файлы попадают в `/opt/var/backups/telemt-ipks` под root, с правами `0700` на каталог и `0600` на IPK и сохранённый SHA-256. Это локальное резервирование **самих пакетов**, а не конфигурации.

Когда на GitHub появится новая версия:

~~~sh
sh upgrade.sh core    # новая версия TeleMT — скачать и проверить, НЕ устанавливать
sh upgrade.sh panel   # новая версия Panel Lite — скачать и проверить, НЕ устанавливать
~~~

Скрипт проверит, что версия действительно выше установленной (через `opkg compare-versions`), скачает проверенный GitHub IPK, прочитает из него `Package`, `Version`, `Architecture`, отвергнет неожиданные maintainer-скрипты и пути конфигурации, и потребует **локально сохранённый и проверенный IPK прежней версии**.

**Пока не реализован и не испытан на устройстве безопасный автоматический rollback, `upgrade.sh` сознательно не имеет `--apply`.** Он только подготавливает файлы и сообщает об отсутствии необходимых резервных копий. Действительное обновление остаётся **ручным**, по процедуре ниже, с резервной копией конфигурации и состояния и перезапуском только нужной службы. Обновление самой панели особенно чувствительно: HTTP-процесс не должен убить механизм отката.

### Чтение metadata IPK без `opkg info`

Entware IPK — это **внешний gzip-compressed tar** с вложенным `control.tar.gz`. Поэтому ни `ar t file.ipk`, ни `tar -tf file.ipk` не обязаны работать; `opkg info /path/file.ipk` также не читает его как обычный индексированный пакет. Для диагностики:

~~~sh
tar -xzOf /opt/tmp/telemt-ipk/telemt_3.5.17-1_aarch64-3.10.ipk ./control.tar.gz |
  tar -xzOf - ./control |
  grep -E '^(Package|Version|Architecture):'
~~~

Для панели используйте фактическое имя скачанного IPK. Версия внутри её `control` — `1.0.0~rc.3-1`, несмотря на `.rc.3` в имени GitHub Release asset.

## «Сервер» в TeleMT Panel и почему обновление через него — отдельный путь

> **Важно для установленной TeleMT Panel 1.x:** оставьте на вкладке «Сервер → Обновления» режим **«Выкл.»** для обоих компонентов, если хотите поддерживать установку из Entware IPK. Режимы «Уведомлять» и «Устанавливать» относятся к штатным *upstream* GitHub-релизам, **не к нашему IPK-каналу**. Не меняйте `updates.telemt_repo` или `updates.panel_repo` на `saymer-alt/entware-go`: в общем Release `latest` лежат IPK, тогда как текущий движок панели ищет архивы `*.tar.gz` с бинарниками и ожидает SemVer-теги. Он не проверяет SHA-256 release asset при установке из интерфейса и не обновляет базу `opkg`.

**Для полноценной интеграции нужна доработка исходного кода самой панели**, а не `Makefile` IPK: новый opt-in режим `entware_ipk`, выбор только доверенных package assets, контроль `digest` и метаданных внутри IPK, согласованный `opkg`-rollback и независимый worker при самообновлении. Требования и тесты описаны в [Issue #30](https://github.com/saymer-alt/entware-go/issues/30). Пока режим отсутствует в собранном бинарнике, страница «Сервер» не может переключиться на этот источник.

У официальной TeleMT Panel 1.x **уже есть раздел управления обновлениями**. Он использует источники и пути из `[updates]`, команды `[host.commands]` и собственный механизм обновления бинарников/worker (см. [официальную документацию Entware](https://github.com/amirotin/telemt_panel/blob/v1.0.0-rc.3/docs/ENTWARE.md) и [конфиг](https://github.com/amirotin/telemt_panel/blob/v1.0.0-rc.3/docs/CONFIG.md)). Это **не** установщик пакетов из `saymer-alt/entware-go` и он не синхронизирует базу `opkg`.

Если используется данный неофициальный IPK-канал, **не смешивайте обновление через официальный UI с обновлением через `opkg`**, пока поведение и откат не адаптированы и не проверены. Для настоящей кнопки «Обновить из Entware IPK» понадобится отдельная серверная интеграция: авторизованный локальный обработчик, чтение одного фиксированного GitHub Release, строгая проверка хэшей и версии, явное подтверждение, резервная копия, управляемый перезапуск и откат. Нельзя просто запускать произвольную shell-команду из поля браузера.

**Публичная часть**: общая инструкция, код без секретов, методы проверки выпусков. **Локальная часть**: домен, SNI, пользователи, пароли, ключи, рабочие TOML, список служб, резервные копии и приватный скрипт конкретного устройства. Ничего из локальной части в Pull Request, GitHub Actions logs или Release выкладывать не нужно.
